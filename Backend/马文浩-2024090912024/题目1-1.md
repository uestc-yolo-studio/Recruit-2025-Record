# 1.1 创世咒语：Java的编译与运行魔法

## 1.1.1 魔法的两种流派

### （1)  两种流派的定义及运行过程的不同点				

- **编译型语言**：在程序运行之前，通过编译器将源代码一次性翻译成目标机器的机器码（可执行文件）。
- **解释型语言**：在程序运行时，解释器逐行读取源代码，逐行解释执行，不生成独立的可执行文件。
- **运行过程的不同**：编译型语言编译成可执行文件后执行，解释性语言逐行解释并执行代码。

### （2)  Java的流派归属及兼具二者特色的原因

​	 Java 属于**半编译半解释型**。

- **编译：**Java内置编译器 javac，Java 源代码（`.java`文件）通过编译器（`javac`）编译成字节码（`.class`文件）。
- **解释：**在运行时，Java 虚拟机（JVM）中的解释器会逐行解释字节码执行。
- **跨平台原因：**javac编译后会生成唯一性的字节码，不同平台的 JVM，翻译字节码为平台对应的机器码而后运行。所以只需一次编译生成字节码，在任何有 JVM 的平台都能运行，即 “一次编译，到处运行”。

### （3）JVM与JIT扮演角色及协作原理

- **JVM**：是 Java 程序运行的 “容器”，负责加载字节码、管理内存、执行字节码等。将字节码翻译成为平台所适配的机器码。
- **JIT**：在 JVM 运行过程中，监测代码执行情况，将频繁执行的热点代码从字节码编译成机器码，缓存起来，后续在翻译这些字节码时直接使用缓存起来的机器码。
- **协同工作**：程序启动时，JVM 的解释器先解释执行字节码，同时 JIT 分析代码执行频率。当某段代码被判定为热点代码后，JIT 将其编译为机器码并缓存，之后该段代码执行时，直接使用编译后的机器码，解释器和 JIT 配合，既保证了启动速度，又保证了运行效率。

## 1.1.3 魔法的本质

### （1） Java 的语言类型及与 Python 类型系统异同

- Java 是**静态语言**。
- **与python异同**
  - **相同点：**都有类型系统，用于约束数据的操作。
  - **不同点：**Java 类型检查在编译期，Python 在运行期；Java 变量类型声明后相对固定，Python 变量类型灵活可变。

### （2）Java的 **“动态”** 潜能。

- **反射机制**：运行时可以获取类的信息（如构造方法、方法、字段等），并能动态创建对象、调用方法、访问字段，无需在编译期确定这些操作的具体类和方法。
- **动态代理**：在运行时动态生成代理类，实现对目标对象方法的增强等操作，无需提前编写代理类的代码。

### （3）Java 类型系统的优势与局限

- 优势
  - **编译期类型检查**：能在编译阶段发现很多类型相关的错误，减少运行时错误，提高程序可靠性。
  - **执行效率高**：静态类型让 JVM 在运行时对类型更明确，便于 JIT 进行优化，生成更高效的机器码。
  - **代码可读性和可维护性好**：明确的类型声明让代码更易理解，团队协作时也更方便。
- 局限
  - **开发效率稍低**：需要编写更多的类型声明代码，尤其是在处理一些灵活的数据结构时，不如动态语言简洁。
  - **灵活性不足**：对于一些需要高度动态性的场景（如快速原型开发、灵活的配置化逻辑等），不如 Python 等动态语言灵活。
  - **运行速度较慢**：相较于C++、C，运行速度更慢一些。
