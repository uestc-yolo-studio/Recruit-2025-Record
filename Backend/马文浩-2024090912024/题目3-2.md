# 3.2 封装、继承与多态

## 3.2.1封装

#### （1）运用封装

封装了3.1中的动物朋友代码（仅增添对成员变量的保护）

#### （2）封装的作用

封装能隐藏对象的内部实现细节，只对外提供有限且安全的访问接口。就像给宠物的生命核心数据加上了一道锁，只有通过合法的权限才能对数据进行操作。这样一来，外界无法随意篡改数据，避免了因错误操作导致数据混乱，保证了系统内部数据的安全性。同时，也便于对数据的访问和修改进行统一管理和控制，让系统的运行更加稳定、可控。

#### （3）静态变量、方法、代码块

- **静态变量**：属于类，所有该类的对象共享同一个静态变量。例如，统计宠物种族的数量，这个数量对于整个种族的所有个体来说是共同的，就可以用静态变量。
- **静态方法**：属于类，不需要创建对象就可以通过类名调用。静态方法中只能访问静态变量和调用静态方法，因为非静态的成员属于对象，在静态方法调用时可能还没有对象创建。
- **静态代码块**：在类加载时执行，且只执行一次，通常用于对静态变量进行初始化等操作。

#### （4）计数器的实现

类中定义静态变量  `private static int count = 0`;当创建新对象自增count。

## 3.2.2 继承

#### 继承生命之树：

- 核心特性是子类可以继承父类的属性和方法，从而实现代码的复用，减少代码复杂度。
- 重写父类方法：重新写一个与父类方法名相同的方法，在调用时即可直接使用子类的重写方法，而不是继承父类的特性。
- 子类构造中 **super** 和 **this** 关键字：**super**用于调用父类的构造方法、属性或方法。在子类构造方法中，**super()**可以调用父类的构造方法，要放在子类构造方法的第一行，也可以在已发生代码重写的情况下，仍然使用**super**来调用父类的方法；this 用于调用本类的构造方法、属性或方法，比如在本类构造方法中调用另一个构造方法 、**this**(参数)；两个关键字很多情况下都是为了代码复用。
- “抽象蓝图”（抽象类）：抽象类是用 **abstract** 修饰的类，它不能被实例化，只能被继承。抽象类中可以有抽象方法（用 **abstract** 修饰，只有方法签名，没有方法体）和普通方法。在构建生命之树时，抽象类可以作为父类，定义一些通用的属性和方法，让子类去实现抽象方法，从而规范子类的行为，同时实现代码复用。

#### 接口相关概念：

- **接口**：可以理解为一种 “能力规范” 的约定。它里面定义了一些方法，但没有方法的具体实现，需要类去承接实现
- 接口和抽象类的本质区别：
  - 抽象类可以有部分方法的实现，也可以有成员变量；而接口主要是定义方法的规范，更侧重于 “能力” 的约定。
  - 一个类只能继承一个抽象类，但可以实现多个接口，更加具有实用性。

## 3.2.3多态

#### 情景解读

父类引用指向子类实例：若有父类Pet，子类Dog可以创建子类实例`Pet aDog = new Dog()`;

方法重写：若父类有一方法为work();而子类在继承后想构建新的work方法，则在定义子类时重新构建work()函数；

接口引用指向实现类实例：若定义接口Speak()，再构建实现类wolf()，meow(),创建实例`Speak speakCritical = new wolf()`;

#### `instanceof`关键字

若想知道父类引用指向的是否是某个实例，可以用 `Father instanceof Son`返回的布尔变量得知；
