# 1.2  魔力指针，理解“引用”的奥秘

## 1.2.1探寻指针的踪迹

### （1）Java中类似C++指针的存在

**引用**是Java中类似指针的存在，在牺牲部分功能的情况下，获得了更好的安全性。

### （2）Java 的 “引用” 的定义及与指针相比的优势

Java 的 “引用” 是**指向堆中对象的 “句柄”**（存储对象的内存地址，但对开发者透明）。与 C 指针相比：

- **安全性**： 引用不会指向非法内存，垃圾回收器（GC）可通过引用追踪对象，防止内存泄漏，因此开发者无需耗费精力关注指针使用所造成的内存问题，如 “野指针”“指针越界” 等。
- **简便性**：开发者无需手动管理内存，也无需关注指针偏移、内存布局等底层细节，降低了开发难度。

### （3）Java 的参数传递：值传递还是引用传递？

**Java 只有 “值传递”**。

- 传递**基本类型**时，传递的是 “值的副本”，方法内修改不影响外部变量；
- 传递**引用类型**时，传递的是“引用副本”，即把 “指向对象的地址” 复制了一份给方法的参数，而非将原参数引用传递，例如若修改引用副本指向，原参数指向不会受影响，可以证明其为值传递。

## 1.2.2引用的四种形态

### （1）四种引用的特性与 “断开连接” 时机

- **强引用**：最普通的引用（如`Object obj = new Object()`）。只要强引用存在，GC 永远不会回收被引用的对象；只有当强引用被置为`null`或超出作用域时，对象才可能被回收。
- **软引用**：GC 在**内存充足时**不会回收软引用对象；当**内存不足时**，会回收软引用指向的对象。
- **弱引用**：无论内存是否充足，**只要发生 GC**（即使是 Minor GC），若对象只有弱引用指向它，就会被回收。
- **虚引用**：必须与`ReferenceQueue`配合使用。虚引用对对象的生存周期无影响，唯一作用是**在对象即将被回收时，通过引用队列接收通知**（用于跟踪对象回收过程）。

### （2）适用场景

- **强引用**：日常开发中最常用的引用，用于普通对象的访问与持有，保证对象正常可用。
- **软引用**：适合构建**内存敏感的缓存**（如图片缓存）。内存充足时缓存有效，内存不足时自动回收，避免内存溢出（OOM）。
- **弱引用**：适合**生命周期短暂且需自动回收的场景**，如`ThreadLocal`的实现（防止线程局部变量内存泄漏）、对象回收监控。
- **虚引用**：适合**对象回收前的特殊处理**（如直接内存的释放）。例如`ByteBuffer`的`cleaner`机制，利用虚引用在直接内存对象回收前，触发堆外内存的清理。

## 1.2.3实践中的洞察

### （1）代码输出预测

代码的输出是`hello`。

### （2）从 Java 内存模型角度的解释

1.**字符串常量池**：当执行`String str = "hello";`时，Java 会先检查字符串常量池。如果常量池中已经存在`"hello"`，就直接将`str`引用指向常量池中的`"hello"`；如果不存在，就会在常量池中创建`"hello"`，然后让`str`引用它。

2.**栈与堆的交互**：

- 在`main`方法中，`str`是一个局部变量，存储在栈中，它保存的是对字符串常量池里`"hello"`的引用。
- 当调用`change`方法时，会将`str`的引用值（即指向`"hello"`的引用）传递给`change`方法的参数`s`。此时，`s`在栈中也保存了指向`"hello"`的引用。
- 在`change`方法内部，执行`s = s + " world";`。由于字符串是不可变的，`s + " world"`会在堆中创建一个新的字符串对象`"hello world"`，然后`change`方法中的`s`引用会指向堆中的这个新字符串对象。但需要注意的是，`main`方法中的`str`引用并没有被改变，它仍然指向字符串常量池中的`"hello"`。
- 当`change`方法执行完毕后，`s`这个局部变量会随着方法栈帧的弹出而销毁，但`main`方法中的`str`引用不受影响。所以最后执行`System.out.println(str);`时，输出的还是`"hello"`。
