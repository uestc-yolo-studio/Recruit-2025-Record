**1.**：了解并阐述成员内部类、静态内部类、局部内部类和匿名内部类的定义、特点及适用场景。

成员内部类是定义在另一个类的内部，并且与类的成员（字段、方法）处于同一级别。它是最普通的内部类形式。**依赖实例**：成员内部类的对象**必须依赖于一个外部类的对象**而存在。不能直接通过 `new Inner()` 创建，必须先创建外部类实例。**完全访问权限**：成员内部类可以无条件地访问**外部类的所有成员（包括`private`成员）**，这是因为内部类对象隐式持有一个指向外部类对象的引用（`Outer.this`）。**自身是成员**：在外部类内部，可以像使用普通成员一样使用它（如 `this.new Inner()`）。在外部类之外，需要遵循访问控制规则（如`private`内部类则外部不可见）。适用场景是当内部类和外部类之间存在紧密的“组成部分”关系时

静态内部类是使用 `static` 关键字修饰的、定义在另一个类内部的类。它也称为**嵌套类**。特点：**不依赖实例**：静态内部类的对象**不依赖于外部类的实例**。可以像普通类一样直接创建。**访问限制**：静态内部类**只能直接访问外部类的静态成员**（包括私有静态成员）。它不能直接访问外部类的实例成员（因为没有外部类对象的引用）。并且是完全独立的

局部内部类定义在一个**方法**或**作用域块**（如`if`块、`for`循环）内部的类。它的作用范围仅限于定义它的代码块。特点是**作用域限制**：局部内部类只在定义它的方法或作用域内可见，出了这个范围就无法使用。**访问外部成员**：和成员内部类一样，可以访问外部类的所有成员。**访问局部变量**：可以访问方法中的**final或等效final（effectively final）** 的局部变量。这是因为局部变量的生命周期与方法调用相同，而内部类对象的生命周期可能更长，Java通过复制引用来解决这个问题，并要求变量不可变以保证数据一致性。适用场景是当一个类在某个方法内部需要使用一次，并且逻辑非常特定于该上下文时

匿名内部类是没有显式类名的局部内部类。它通常用于**一次性**创建一个类的子类实例或一个接口的实现类实例。适用场景主要是需要快速实现或继承一个类。

链式调用的方式不仅简洁并且可读性强

使用这种**静态内部类 Builder 模式**，相比传统的构造方法，主要带来了以下核心优势：

| 特性             | 传统构造方法             | Builder模式                               |
| :--------------- | :----------------------- | :---------------------------------------- |
| **多参数可读性** | 差（参数顺序易错）       | **极佳**（方法名自描述）                  |
| **可选参数处理** | 笨拙（需重载或传null）   | **灵活优雅**（默认值 + 链式设置）         |
| **对象不可变性** | 实现复杂                 | **天然支持**                              |
| **构建安全性**   | 校验困难                 | **易于校验**（构造器、方法、build）       |
| **代码扩展性**   | 差（新增参数需改构造器） | **好**（新增参数只需在Builder中添加方法） |
