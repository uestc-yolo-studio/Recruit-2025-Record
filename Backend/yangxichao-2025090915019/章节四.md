## sql语句练习

```sql
-- 基础咒语

SELECT * FROM students WHERE `name` LIKE '张%' || `name` LIKE '李%';

SELECT * FROM students WHERE year(birth_date) = 2003 && gender = 'F';

SELECT * FROM scores WHERE score < 90 && score > 80;

SELECT name,email FROM students LIMIT 5;

SELECT * FROM students WHERE `name` LIKE '%三%';

-- 进阶咒语

SELECT class_id,COUNT(*) as total FROM students GROUP BY class_id HAVING total > 2;

SELECT student_id,SUM(score) as sum FROM scores GROUP BY student_id ORDER BY sum DESC LIMIT 3;

SELECT teacher_id,course_name FROM courses ORDER BY teacher_id;
SELECT course_id,COUNT(student_id) FROM scores GROUP BY course_id;

SELECT course_id,AVG(score),MAX(score),MIN(score) FROM scores GROUP BY course_id;

SELECT student_id FROM scores WHERE course_id IN(1,2) GROUP BY student_id HAVING MIN(score) >= 85;
```

## 遇到的问题

### Q1

![](../../../../question/屏幕截图 2025-10-03 223513.png)

这样写只能查询某个老师教的其中一门课程。原因是当一个教师`teacher_id`对应多门课程时，数据库无法确定应该显示哪一门课程的 `course_name`。后来又找到了分组查询的规则：select的子句中只能是被group by包含的字段或者被聚合函数处理的字段。将group by改成order by就可以了。

### Q2

<img src="../../../../question/屏幕截图 2025-10-03 225938.png"  />

这样查询会将选修了课程1和2，但是其中一门课达标，但另一门课不达标的学生也找出来。仔细分析后发现这个sql语句会一个学生一个学生的查找，只要查到有一个学生的课程是其中一门且成绩达标，他就会被选上。因此要先判断学生是否选修了课程1或2，再把学生分组，判断其成绩的最小值是否达标。

## 表结构优化

+ 创建status的索引

	```sql
	create index idx_orders_statues on orders(statues);
	```

+ 分区表，按照statues列表分区

## sql查询优化

+ 避免使用 select * ，只查询需要的字段(如user_id,product_name)
+ 如果需要查询所有字段，可以使用覆盖索引，即创建索引时包含所有字段，可以避免回表

## redis

- 将“已支付”订单的ID列表或常用字段存入 Redis
- 使用 `SET` 或 `ZSET`（按时间排序）存储订单ID
- 设置合理的过期策略（如30分钟）
