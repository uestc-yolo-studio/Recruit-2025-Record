## 编译型与解释型

#### (1)

编译型:通过编译器将源代码转化为机器语言生成可执行文件，之后可以无限次运行

解释型:源代码在运行时由解释器逐行转化为机器语言，每次执行时都需要重新解释

#### (2)

按照Java代码的执行方式，Java应该是半编译半解释的语言，Java的编译器会将源代码编译成字节码，并保存      在class文件中，然后Java解释器对字节码进行解释执行。
编译成字节码后，JVM（Java虚拟机）负责在不同操作系统上加载并运行class文件，现代的JVM中内置了JIT编译器，提高了效率。

#### (3)

 JVM以解释的方式执行字节码，同时会找出被频繁执行的热点代码，然后JIT编译器会即时将这些代码整体编译成本地机器码，并优化储存起来，下次执行同样的代码时JVM就会直接运行已经编译好的本地机器码，这样就结合了解释器启动快和编译器运行快的优点。

## Java程序流程图

Java源代码---^编译器编译^--->字节码(class文件)---^JVM解释(JIT优化)^--->本地机器码(运行)

### 探寻指针的踪迹

#### (1)

Java 中不存在和 C 语言完全一样的指针。C 语言的指针可以直接操作内存地址，而 Java 为了安全，避免了这种直接的内存操作，采用 “引用” 来实现类似的功能，但限制更多。

#### (2)

- **引用的定义**：Java 中的引用是指向对象在堆内存中地址的一种标识，通过引用可以操作对象。

- 与指针的对比及优势

	：

	- **安全性**：指针可能因错误操作（如野指针、指针越界）导致内存泄漏、程序崩溃等问题，而 Java 引用不会出现这些情况，因为它不能直接操作内存地址，由 Java 虚拟机（JVM）管理内存，进行垃圾回收等操作，减少了内存相关的错误。
	- **简便性**：开发者不需要关心内存的分配和释放等底层细节，专注于业务逻辑开发即可，提高了开发效率。

#### (3)

Java 中只有值传递。当传递基本数据类型时，传递的是值的副本；当传递引用数据类型时，传递的是引用（即对象地址）的副本。虽然传递引用数据类型时，方法内通过引用副本可以修改原对象的内容，但本质上还是传递的是值（引用的值），所以是值传递。

### 引用的四重形态

#### （1）

- **强引用**：是最普通的引用，只要强引用存在，垃圾回收器就不会回收被引用的对象。只有当强引用被置为`null`时，才可能断开与对象的连接，让对象有机会被回收。
- **软引用**：当 JVM 内存不足时，会回收被软引用指向的对象。也就是在内存紧张的情况下，会自动断开与对象的连接。
- **弱引用**：不管内存是否充足，只要发生垃圾回收，被弱引用指向的对象就会被回收，即垃圾回收发生时，就会自动断开连接。
- **虚引用**：虚引用必须和引用队列（`ReferenceQueue`）一起使用，它的作用是在对象被回收时收到通知。当对象即将被回收时，虚引用会被加入到引用队列中，从而断开与对象的连接（实际是通过引用队列来感知对象的回收）。

#### （2）

- **强引用**：适用于一般的对象引用场景，只要对象还在使用，就保持引用，确保对象不被回收。
- **软引用**：适合构建缓存，比如图片缓存，当内存足够时，缓存的图片对象（被软引用指向）不会被回收；内存不足时，回收这些对象，释放内存。
- **弱引用**：可用于监控对象回收，比如在一些框架中，通过弱引用关联对象，当对象被垃圾回收时，能感知到，从而进行一些清理操作。
- **虚引用**：主要用于对象回收的通知机制，例如在 NIO（非阻塞 I/O）中，用于跟踪直接内存（堆外内存）的分配和释放，当直接内存对应的对象被回收时，通过虚引用和引用队列来通知进行内存释放等操作。

### 实践中的洞察

只会输出hello。
当执行String str = "hello"时，会先检查字符串常量池，发现没有hello，然后创建一个hello。
str是一个引用变量，存储在栈中，引用串池中的hello。
当调用change方法时，将str引用的值传给s，此时s也指向hello。
由于字符串的值不能被修改，所以s = s + " world"相当于在堆中创建一个新的“hello world”对象，并让s指向它。
最终str仍然指向串池中的hello，所以输出hello。
